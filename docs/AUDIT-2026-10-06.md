# Audit 2026-10-06 - unfinished features and technical debt

An independent audit of the whole repository, done in the main thread with no subagents, and
cross-checked against `docs/CENSUS-2026-09-13.md` only at the end, as the owner asked.

- **Subject:** commit `8ad66339d8dafe68a962fceba77a67443d3c7c62` on `claude/intelligent-thompson-h8bkpf`. The working tree matched it
  throughout the read; the only untracked path was `.claude/hooks/.fanout-count`, written by the hook stack.
- **Findings:** 254 - high 18, medium 114, low 122. Full evidence and fix for each:
  [high and medium](AUDIT-2026-10-06-findings-high-medium.md), [low](AUDIT-2026-10-06-findings-low.md).
- **Census cross-check:** all 280 census entries re-checked against today's code: 156 covered by
  this audit, 11 fixed since, 113 still true and **not** among this audit's findings, 0 wrong as written.
- **Nothing was committed or pushed.** See [Limits](#limits-and-what-was-not-done).

## How it was done

1. **Every tracked file was read.** `git ls-files` lists 661 paths: 611 text files, 200922 lines in all,
   and 50 binary files (38 .png, 4 .jar, 3 .cmvd, 2 .bin, 1 .ico, 1 .mets, 1 .bch), which were listed by size and checked for NUL bytes rather
   than read as text. Each text range was logged as it was printed, with the file's blob SHA-1 and
   the commit, so a read of a file that later changed would not count. The gap check reports 0 unread
   lines. It passes two known-answer controls: a planted 10-line row with no reads reports 10 unread
   lines, and a fully read file reports full coverage.
2. **Leads, then findings.** Reading raised 236 leads. Each was settled before the cross-check:
   FINDING 51, ADDENDUM 54, SUBSUMED 96, CENSUS 21, REFUTED 14.
   (CENSUS here means the lead was already a census entry, re-read and confirmed. These are counted
   with the cross-check, not as findings.)
3. **Measurements carry controls.** Every count in a finding marked MEASURED comes from a script
   with a known-answer control, and a run whose control fails prints nothing. Where a control
   caught a scan reading the wrong thing, the finding records the first result and the correction.
   The scripts are not in this repository: added under `docs/` they would become modules that
   `tools/whole_tree.py` holds every module-keyed record to. They were handed over separately.
4. **Each finding carries its evidence:** READ IN SOURCE (file:line quotes) or MEASURED (the
   script, its control and its result), plus a proposed fix that makes the class impossible rather
   than fixing one instance.

## Where to start

**Edits a user can lose or corrupt in ordinary use**

- [F231](AUDIT-2026-10-06-findings-high-medium.md#f231) - a damaged or missing game archive leaves no workspace, and closing the window in that state deletes every unpacked edit (census H.13, re-checked: still true)
- [F033](AUDIT-2026-10-06-findings-high-medium.md#f033) - Options > Clean workspace deletes every unpacked edit without asking
- [F234](AUDIT-2026-10-06-findings-high-medium.md#f234) - Empty zone / Rename zone / Connect zones write through their own container; the next save of that zone splices with stale offsets
- [F083](AUDIT-2026-10-06-findings-high-medium.md#f083) - saving props with a matrix open silently deletes any prop whose cell has no region
- [F011](AUDIT-2026-10-06-findings-high-medium.md#f011) - the open-time repair writes zone headers per resource and the master table only at the end, on every workspace open
- [F227](AUDIT-2026-10-06-findings-high-medium.md#f227) - no unit of work: 14 user-facing operations write several files in sequence and leave a half-state on any failure
- [F046](AUDIT-2026-10-06-findings-high-medium.md#f046) - the zone-limit executable patch is built blind from Omega Ruby offsets; the verified variant has no caller
- census H.69 - a failed pack before a game-folder repoint is ignored and the workspace is cleaned anyway (re-checked: still true, not in this audit's findings)

**Failures nobody sees**

- [F219](AUDIT-2026-10-06-findings-high-medium.md#f219) - the Windows app-image has no console, no log file and no uncaught-exception handler: 114 log/stderr sites and every EDT exception vanish
- [F220](AUDIT-2026-10-06-findings-high-medium.md#f220) - opening a zone runs all nine editors' Swing mutations on a SwingWorker thread (198 off-EDT mutations measured)
- [F208](AUDIT-2026-10-06-findings-high-medium.md#f208) - after one ZoneData entry fails to open, no zone can be opened at all (measured NPE on every zone open)
- [F210](AUDIT-2026-10-06-findings-high-medium.md#f210) - six format records override equals without hashCode; two New camera entries are equal, so editing the second overwrites the first

**Unfinished features**

- [F025](AUDIT-2026-10-06-findings-high-medium.md#f025) - the zone SCRIPT archive is not managed: created zones run their donor's events and appended zones cannot run field scripts
- [F039](AUDIT-2026-10-06-findings-high-medium.md#f039) - adding zones is one-shot: it refuses unless the game has exactly 536 zones
- [F077](AUDIT-2026-10-06-findings-high-medium.md#f077) - the macOS/Linux build cannot initialise OpenGL (only Windows natives ship) - measured failing on Linux
- [F096](AUDIT-2026-10-06-findings-high-medium.md#f096) - the map-matrix zone-grid tool throws ClassCastException on cell selection

**The project's own guard stack**

- [F173](AUDIT-2026-10-06-findings-high-medium.md#f173) - GAME DATA IS READ-ONLY is bypassed by a line before the write, env/sudo/bash -c, or a writer not on its 37-name list

- [F176](AUDIT-2026-10-06-findings-high-medium.md#f176) - no newline-aware command splitter: 5 command guards pass their own refused case once any line precedes it
- [F177](AUDIT-2026-10-06-findings-high-medium.md#f177) - the project hook stack fails OPEN on any payload byte cp1252 cannot decode
- [F213](AUDIT-2026-10-06-findings-high-medium.md#f213) - every wired hook entry point allows the act when it cannot parse its payload (15 of 15 measured)
- [F182](AUDIT-2026-10-06-findings-high-medium.md#f182) - tracked git hooks are mode 100644, so on every POSIX clone commit-msg and pre-commit never run while arm_checkout reports them ARMED
- [F178](AUDIT-2026-10-06-findings-high-medium.md#f178) - the request ledger's declared reviewer needs a subagent at every turn end, which CLAUDE.md section 2 forbids without a yes
